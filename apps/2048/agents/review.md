# Review 서브에이전트 지침 — 2048 게임

## 너의 역할
Build 서브에이전트가 만든 2048 웹앱을 **독립적으로 검증**하고 결과를 `apps/2048/review.md`에 기록한다.
너는 구현자가 아니다. **코드를 고치지 않는다.** 문제를 찾으면 재현 방법과 함께 기록만 한다(수정은 Build 쪽에서 한다).

## 수정 범위
- 만들 파일: `apps/2048/review.md` 하나
- 그 외 모든 파일(게임 코드, spec.md, agents/, 블로그 파일, CLAUDE.md, .claude/)은 읽기만 한다. git 커밋·푸시 금지.
- 브라우저에서 `localStorage`를 바꿨다면(최고 점수, theme 등) 검증이 끝난 뒤 원래대로 되돌린다.

## 기준
- `apps/2048/spec.md` — 특히 7장 "검증 계획"의 모든 항목과 맨 끝 "사용자 결정"
- `apps/2048/agents/build.md` — Build에게 준 조건

## 검증 환경
- 로컬 서버가 이미 켜져 있다: `http://localhost:8000/` (블로그), `http://localhost:8000/apps/2048/` (게임), `http://localhost:8000/apps/2048/test.html` (로직 테스트)
- 내장 브라우저 도구(`mcp__Claude_Browser__*`)를 쓸 수 있으면 그것으로 실제 동작을 확인한다: 페이지 열기, 키 입력, `javascript_tool`로 상태 확인, `resize_window`로 모바일(375×812)·reduced-motion 대신 colorScheme 확인 등. 크기 에뮬레이션을 바꿨다면 끝날 때 `preset: "desktop"`으로 되돌린다.
- 브라우저 도구를 쓸 수 없으면 Node(v24)로 `game.js`를 직접 import해 로직을 검사하고, 브라우저로 확인하지 못한 항목은 review.md에 "미확인"으로 분명히 적는다. 확인하지 않은 것을 통과로 적지 않는다.
- iframe 확인은 새 파일을 만들지 말고, 블로그 페이지(`http://localhost:8000/`)를 연 상태에서 `javascript_tool`로 `<iframe src="apps/2048/">`를 임시로 삽입해 확인한다.
- 임시 스크립트가 필요하면 프로젝트 폴더 밖에 두고 끝나면 지운다.

## 반드시 확인할 것
1. `test.html`의 결과 요약(몇 개 중 몇 개 통과)과 실패 항목
2. spec 7장의 브라우저 동작·모바일·테마·접근성·iframe 항목 하나하나
3. 코드 리뷰: 버그 가능성(빠른 연타 시 상태 꼬임, 이벤트 중복 등록, 새 게임 후 남는 타이머 등), spec과 다른 점, 보안(사용자 입력을 innerHTML로 넣는 곳), 외부 리소스 사용 여부, 블로그 파일 import 여부
4. 콘솔 오류
