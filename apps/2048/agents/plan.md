# Plan 서브에이전트 지침 — 2048 게임

## 너의 역할
2048 웹앱의 **계획서(spec)만** 작성한다. 코드는 쓰지 않는다.

## 수정 범위 (이 밖의 파일은 절대 만들거나 고치지 않는다)
- 만들 파일: `apps/2048/spec.md` 하나

읽기는 자유롭게 해도 된다. 특히 아래 파일을 읽고 블로그와 어울리게 계획한다.
- `CLAUDE.md` — 프로젝트 규칙과 작업 사이클
- `css/style.css` — 블로그 색상 변수(`--bg`, `--text`, `--accent` 등)와 `:root[data-theme="dark"]` 다크 모드
- `index.html`, `js/theme.js` — 테마는 `localStorage`의 `theme` 키(`light` | `dark`), 없으면 OS 설정을 따른다

## 사용자 요청
> 2048 게임을 만들어줘. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이야. 점수판도 넣어줘.

## 지켜야 할 조건
- HTML, CSS, JavaScript만 사용. 빌드 도구·npm 없음. 외부 라이브러리는 꼭 필요할 때만(CDN 허용), 가능하면 쓰지 않는다.
- 앱은 `apps/2048/` 안에서 자체 완결된다. 블로그의 CSS/JS를 import하지 않는다(색상 값은 복사해서 써도 된다).
- 모바일에서도 플레이 가능해야 한다: 방향키 + 터치 스와이프, 375px 폭에서 가로 스크롤 없음.
- 블로그처럼 라이트/다크 모드를 지원한다(같은 `theme` 저장값과 OS 설정을 따른다).
- 나중에 블로그 메인 페이지에 카드로 넣을 것이므로, iframe 안에서도 잘 보이고 동작해야 한다.

## spec.md에 반드시 들어갈 내용
1. **개요** — 한두 문장 요약
2. **기능 목록** — 꼭 필요한 것(MVP)과 있으면 좋은 것을 구분. 최소한 다음을 포함:
   - 4×4 보드, 시작 시 타일 2개, 이동마다 새 타일(2: 90%, 4: 10%)
   - 방향키·WASD·스와이프 이동, 한 번 이동에 같은 타일은 한 번만 합쳐짐
   - 점수판: 현재 점수, 최고 점수(`localStorage` 저장), 합칠 때 점수 증가 표시
   - 새 게임 버튼, 2048 달성 시 승리 안내(계속하기 가능), 더 이상 움직일 수 없으면 게임 오버 안내
3. **게임 규칙과 알고리즘** — 한 줄(행/열) 밀기·합치기 방법, 이동 가능 여부 판정, 게임 오버 판정
4. **파일 구조** — `apps/2048/` 아래 파일과 각 파일의 역할. 게임 로직(순수 함수)과 화면 그리기를 분리해 로직만 따로 테스트할 수 있게 한다.
5. **화면 구성** — 데스크톱/모바일 레이아웃, 점수판 위치, 타일 색상 규칙(라이트·다크), 애니메이션(이동·합침·등장)
6. **접근성** — 키보드 조작, 점수·게임 상태를 화면 낭독기에 알리는 방법, `prefers-reduced-motion`
7. **검증 계획** — Review 단계에서 확인할 항목 목록(브라우저 동작, 모바일, 로직 엣지 케이스: 예 `[2,2,2,2]` → `[4,4,0,0]`, `[2,2,4,0]` → `[4,4,0,0]`)
8. **블로그 카드(Embed) 계획** — 카드 제목, 한 줄 설명, 미리보기 방식(이미지 또는 iframe)과 그 이유
9. **범위 밖** — 이번에 하지 않을 것

## 작성 규칙
- 한국어로, 구현하는 사람이 이것만 보고 만들 수 있을 만큼 구체적으로 쓴다. 다만 불필요하게 길게 쓰지 않는다.
- 끝나면 spec.md의 핵심(파일 구조, MVP 기능, 결정이 필요한 점)을 짧게 요약해 보고한다.
