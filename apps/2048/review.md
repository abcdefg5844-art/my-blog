## 발견한 문제

### [심각도: 낮음] 오버레이가 열려 있어도 포커스가 오버레이 밖으로 나감
- 재현 방법: 게임 오버(또는 승리) 오버레이가 뜬 상태에서 Tab/Shift+Tab을 누른다.
- 기대 동작: 오버레이가 보드를 덮는 대화 상자처럼 동작한다면, 포커스가 오버레이 버튼 안에 머물거나 오버레이에 `role="dialog"`와 이름이 붙는다.
- 실제 동작: 포커스가 뒤쪽 "새 게임" 버튼이나 보드로 이동한다. 오버레이 요소에는 role/aria-label이 없다. 기능상 문제는 없다(spec은 "첫 버튼으로 포커스 이동"만 요구하며 이는 충족).
- 관련 위치: `apps/2048/index.html:55`, `apps/2048/index.html:63`, `apps/2048/main.js:265`

### [심각도: 낮음] reduced-motion에서 `+N`이 600ms 동안 정지 상태로 남음
- 재현 방법: OS에서 움직임 줄이기를 켜고 타일을 합친다(코드 리뷰로 확인, 브라우저 미확인).
- 기대 동작: spec 6장은 "점수 떠오름을 모두 끈다(즉시 표시)"라고 한다.
- 실제 동작: 애니메이션은 꺼지지만 `+N` 요소는 그대로 600ms 보였다가 사라진다. 의도된 동작일 수도 있어 선택적으로 손볼 사항이다.
- 관련 위치: `apps/2048/main.js:214-220`, `apps/2048/style.css:557-564`

### [심각도: 낮음] 아주 작은 iframe(300×360)에서 하단이 약 5px 잘림
- 재현 방법: 블로그 페이지에서 `<iframe src="apps/2048/" style="width:300px;height:360px">`로 띄운다.
- 기대 동작: 보드가 잘리지 않는다.
- 실제 동작: 보드 하단이 365px로 iframe 높이(360)를 넘고, 세로 스크롤(373px)이 생긴다. 좁은 폭에서 헤더가 줄바꿈되어 `--chrome: 130px` 추정치보다 커지는 것이 원인으로 보인다. spec이 제시한 카드 크기(모바일 440px, 데스크톱 520px)와 400×400에서는 문제가 없다.
- 관련 위치: `apps/2048/style.css:50`, `apps/2048/style.css:533-536`

### [심각도: 낮음] `alertMessage`에 토큰 처리가 없음
- 재현 방법: 게임 오버 직후 30ms 안에 다시 하기를 누르는 경우(코드 리뷰, 실사용에서는 거의 불가능)
- 기대 동작: 새 게임 뒤에는 이전 게임 오버 알림이 늦게 다시 쓰이지 않는다.
- 실제 동작: `announce`와 달리 `alertMessage`는 setTimeout을 취소하지 않아, 이전 알림 문구가 늦게 들어갈 수 있다. 영향은 매우 작다.
- 관련 위치: `apps/2048/main.js:249-254`

## 재검증 (1차 수정 후)

기준: `apps/2048/agents/build-fix.md`. 내장 브라우저로 다시 확인했다(이번에는 스크린샷 없이 실제 키 입력과 요소 크기 수치로 확인). 승리 오버레이, reduced-motion, 알림 타이밍은 지난번처럼 브라우저 메모리 안의 `main.js` 사본으로 확인했다. 사본에는 상태 노출과 `animationsOn()`에 reduced-motion 강제 플래그만 덧붙였고, 디스크 파일은 바꾸지 않았다.

| iframe 테마 동기화 | 통과 | 블로그 테마 버튼 클릭 → iframe도 light/dark로 즉시 따라감 |
| OS 테마 실시간 전환, 실제 reduced-motion, 실기기 터치 스크롤 | 미확인 | 이전과 같은 도구 한계(코드는 변경 없음 또는 위에서 코드로 확인) |

### 4. 새로 발견한 문제
- 없음.
- 참고(문제 아님): 넓은 화면(1280×720)에서는 `.app`이 화면 높이를 꽉 채우므로 안내 줄 아래가 빈 공간으로 남는다. 의도된 배치로 보인다.

### 정리
- `localStorage`를 검증 전 상태(`2048-best`, `theme` 모두 없음)로 되돌렸다.
- 화면 크기 에뮬레이션을 `preset: "desktop"`으로 되돌렸다. colorScheme은 이번에 바꾸지 않았다.

## 기타 의견
- 한글 자판 상태에서도 WASD가 동작하도록 `event.code`를 함께 보는 처리가 좋다.
- 애니메이션 중 입력이 오면 `finishAnimations()`로 즉시 마무리하고, 로직 상태를 먼저 갱신하는 구조가 spec 5장의 의도와 맞는다. 연타 검증에서 DOM과 로직이 한 번도 어긋나지 않았다.
- 미확인 항목(실기기 터치 스크롤 방지, OS 테마 실시간 전환, reduced-motion 실제 표시)은 실제 휴대폰이나 OS 설정을 바꿔 사람이 한 번 확인하기를 권한다.
