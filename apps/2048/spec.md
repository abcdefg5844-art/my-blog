# 2048 게임 — 계획서 (spec)

## 1. 개요
방향키·WASD·터치 스와이프로 4×4 보드의 숫자 타일을 밀어 같은 숫자를 합치고, 2048 타일을 만드는 퍼즐 게임. 현재 점수와 최고 점수를 보여 주며, 블로그와 같은 라이트/다크 테마를 따르고 블로그 메인 카드의 iframe 안에서도 동작한다.

## 2. 기능 목록

### MVP (반드시 구현)
| # | 기능 | 세부 |
|---|------|------|
| 1 | 4×4 보드 | 시작 시 빈 칸 중 무작위 2곳에 타일 생성 |
| 2 | 새 타일 | **보드가 실제로 바뀐 이동**마다 빈 칸 1곳에 생성. 값은 2(90%) / 4(10%) |
| 3 | 이동 입력 | 방향키, WASD(대소문자 모두), 터치 스와이프. 보드가 바뀌지 않는 이동은 무시(새 타일 없음) |
| 4 | 합치기 규칙 | 한 번 이동에서 같은 타일은 한 번만 합쳐짐 (3장 알고리즘) |
| 5 | 현재 점수 | 합쳐서 생긴 타일 값의 합만큼 증가 |
| 6 | 최고 점수 | `localStorage` 키 `2048-best`에 저장. 현재 점수가 넘으면 즉시 갱신·저장. 저장 실패(try/catch)해도 게임은 동작 |
| 7 | 점수 증가 표시 | 이번 이동에서 얻은 점수를 점수판 위에 `+N`으로 띄웠다가 위로 사라지게(약 600ms) |
| 8 | 새 게임 버튼 | 보드·현재 점수 초기화(최고 점수 유지), 승리 상태 초기화 |
| 9 | 승리 안내 | 2048 타일이 처음 생기면 보드 위 오버레이 “2048 달성!” + [계속하기] [새 게임]. 계속하기 후에는 같은 게임에서 다시 띄우지 않음 |
| 10 | 게임 오버 안내 | 빈 칸이 없고 인접한 같은 값도 없으면 오버레이 “게임 오버” + 최종 점수 + [다시 하기] |
| 11 | 테마 | 블로그와 같은 `theme` 키(`light`\|`dark`)를 읽고, 없으면 OS 설정. 6장 참고 |
| 12 | 반응형·iframe | 375px 폭에서 가로 스크롤 없음, iframe 안에서 키 입력·스와이프 동작 |

### 있으면 좋은 것 (MVP 이후, 사용자가 원하면)
- 되돌리기(Undo) 1회
- 게임 진행 상태 저장(새로고침해도 이어하기, 키 `2048-state`)
- 앱 안의 테마 토글 버튼(현재는 넣지 않음 — 결정 필요 항목 참고)
- 이동 횟수 / 플레이 시간 표시

## 3. 게임 규칙과 알고리즘

### 데이터 표현
- 보드: 길이 16의 숫자 배열 또는 4×4 2차원 배열, 빈 칸은 `0`. (애니메이션을 위해 렌더링 쪽에서는 타일마다 고유 `id`를 가진 객체 목록을 쓴다 — 아래 “애니메이션용 정보” 참고)

### 한 줄 밀기 `slideLine(line)` — 순수 함수
입력: 길이 4 배열(이동 방향 쪽이 인덱스 0이 되도록 정렬된 줄). 출력: `{ line, gained }`.
1. 0을 제거해 값만 모은다: `[2,0,2,4]` → `[2,2,4]`
2. 왼쪽부터 훑으며, 현재 값과 다음 값이 같으면 합친 값(×2)을 결과에 넣고 **두 칸을 건너뛴다**(합쳐진 타일은 다시 합쳐지지 않음). 다르면 현재 값만 넣고 한 칸 이동. 합칠 때 `gained += 합친 값`.
3. 길이 4가 될 때까지 뒤에 0을 채운다.

예: `[2,2,2,2]`→`[4,4,0,0]`(+8), `[2,2,4,0]`→`[4,4,0,0]`(+4), `[4,4,8,8]`→`[8,16,0,0]`(+24), `[2,0,0,2]`→`[4,0,0,0]`(+4), `[2,4,2,4]`→ 변화 없음, `[8,0,8,8]`→`[16,8,0,0]`.

### 방향 처리 `move(board, dir)` — 순수 함수
- `left`: 각 행을 그대로 `slideLine`
- `right`: 각 행을 뒤집어 밀고 다시 뒤집기
- `up`: 각 열(위→아래)을 밀기
- `down`: 각 열을 아래→위 순서로 밀고 되돌리기
- 반환: `{ board, gained, moved }`. `moved`는 이전 보드와 한 칸이라도 다르면 `true`.

### 이동 처리 순서 (상태 갱신)
1. `move` 결과 `moved === false`면 아무것도 안 함
2. 점수 += `gained`, 최고 점수 갱신
3. 빈 칸 하나에 새 타일 추가 (`addRandomTile(board, rng)`; `rng`를 인자로 받아 테스트에서 고정 가능)
4. 승리 판정: 아직 승리 안내 전이고 보드에 2048 이상 타일이 있으면 승리 오버레이
5. 게임 오버 판정

### 이동 가능 여부 `canMove(board)` — 순수 함수
- 빈 칸(0)이 하나라도 있으면 `true`
- 모든 칸에 대해 오른쪽 이웃 또는 아래 이웃과 값이 같으면 `true`
- 그 외 `false` → **게임 오버**

### 애니메이션용 정보
렌더링이 타일 이동을 보여 주려면 “어느 타일이 어디로 갔는지”가 필요하다. 로직 모듈의 `move`가 보조 결과로 각 타일의 `from → to` 위치와 `merged`(합쳐져 생긴 칸), 그리고 이후 `spawned`(새 타일 위치)를 함께 돌려주게 한다. 테스트는 `board`/`gained`/`moved`만 검사해도 된다.

## 4. 파일 구조
```
apps/2048/
├── index.html      # 마크업. head의 인라인 스크립트로 테마를 CSS보다 먼저 적용(깜빡임 방지)
├── style.css       # 색상 변수(블로그 값 복사), 레이아웃, 타일 색, 애니메이션, 다크 모드, reduced-motion
├── game.js         # 게임 로직 — DOM 접근 없는 순수 함수만 (ES module export)
│                   #   createEmptyBoard, slideLine, move, canMove, hasWon,
│                   #   emptyCells, addRandomTile(board, rng), newGame(rng)
├── main.js         # 화면·입력 — 상태 보관, 키보드/스와이프 처리, 렌더링, 점수/최고 점수 저장,
│                   #   오버레이, aria-live 알림, 테마 동기화 (game.js import)
├── test.html       # 로직 테스트 페이지: 브라우저에서 열면 game.js 단위 테스트 결과를 표로 표시
├── spec.md         # 이 문서
└── agents/         # 서브에이전트 지침
```
- 외부 라이브러리 없음. 블로그의 `css/`·`js/`를 import하지 않는다(색상 값만 복사).
- `<script type="module">`을 쓰므로 `file://`이 아닌 로컬 서버(예: VS Code Live Server)로 연다. 블로그도 이미 module을 쓰므로 동일 조건.
- `game.js`는 `Math.random`을 직접 쓰지 않고 `rng` 인자(기본값 `Math.random`)를 받는다 → 테스트 재현 가능.

## 5. 화면 구성

### 레이아웃 (위→아래, 가운데 정렬, 최대 폭 480px)
```
[ 2048 (제목) ]              [ 점수 | 최고 ]
[ 설명: 방향키/스와이프로 합쳐 2048을 만드세요 ]   [ 새 게임 ]
[            4×4 보드 (정사각형)             ]
[ 조작법 안내 한 줄 (작게, muted) ]
```
- 보드 크기: `width: min(100%, 480px)`, `aspect-ratio: 1`. 칸 간격과 타일 크기는 CSS 변수(`--gap`, `--cell`)로, 보드 폭에 비례(`calc`)하게. 375px 폭(좌우 여백 16px) → 보드 약 343px.
- 점수판: 제목 오른쪽에 작은 상자 두 개(라벨 “점수”/“최고”, 큰 숫자). 좁은 화면에서도 같은 줄 유지, 넘치면 줄바꿈.
- iframe 낮은 높이(예: 카드 안 400px 내외)에서도 보드가 잘리지 않도록 `max-width: min(480px, 100%, calc(100vh - 헤더높이))` 형태로 높이도 제한.
- 오버레이: 보드 위에 반투명 배경 + 메시지 + 버튼. 보드 영역 안에만 표시.
- 글꼴: 블로그 `--font-sans` 스택 복사. 타일 숫자는 굵게, 자릿수에 따라 크기 축소(1~2자리 / 3자리 / 4자리 이상).
- `body`에 `touch-action: none`은 보드에만 적용(`.board { touch-action: none; }`)해 스와이프 시 페이지 스크롤·당겨서 새로고침 방지. 페이지 전체 스크롤은 막지 않는다.
- 방향키로 페이지가 스크롤되지 않도록 게임 키 처리 시 `preventDefault()`.

### 색상 (블로그 변수 복사 + 게임 전용 변수)
- 공통: `--bg`, `--text`, `--text-muted`, `--accent`, `--border` 등은 `css/style.css` 값 그대로.
- 게임 전용: `--board-bg`, `--cell-bg`, `--tile-2` … `--tile-2048`, `--tile-super`(4096 이상), 각 타일 글자색.
- 라이트: 보드 `#e5e7eb` 계열, 빈 칸 `#f3f4f6`. 타일은 낮은 값일수록 옅고 높을수록 진한 **파랑(블로그 accent #2563eb) 계열 단계**, 2048은 강조색(예: 주황/금색)으로 구분. 2·4는 어두운 글자, 8 이상은 흰 글자.
- 다크: 보드 `#1c1e22`, 빈 칸 `#2d2f34`. 타일은 같은 단계를 어두운 배경에 맞게 채도·밝기 조정(낮은 값은 `#1b2638` 계열, 높은 값은 `#60a5fa` 계열). 글자 대비 WCAG AA(4.5:1, 큰 글자 3:1) 이상.
- 정확한 hex 표는 Build 단계에서 정하되, 위 규칙과 대비 기준을 지킨다.

### 테마 적용
- `index.html` head 인라인 스크립트: 블로그와 똑같이 `localStorage.theme` → 없으면 `prefers-color-scheme` → `<html data-theme>` 설정.
- CSS는 `:root[data-theme="dark"]`와, JS가 꺼졌을 때의 `@media (prefers-color-scheme: dark) :root:not([data-theme])` 대비책을 블로그와 같은 구조로.
- `main.js`: 저장값이 없을 때 OS 설정 변경(`matchMedia change`)을 따라가고, `window`의 `storage` 이벤트(`key === 'theme'`)를 들어 **부모 블로그에서 테마를 바꾸면 iframe도 즉시 바뀌게** 한다(같은 출처이므로 localStorage 공유).
- 앱 안에는 테마 토글 버튼을 두지 않는다(결정 필요 항목 참고).

### 애니메이션 (CSS transform/transition)
- 타일은 절대 위치 + `transform: translate(x, y)`로 배치. 이동: `transition: transform 100ms ease-in-out`.
- 합침: 이동이 끝난 뒤 합쳐진 타일에 `pop` 키프레임(scale 1 → 1.15 → 1, 150ms).
- 등장: 새 타일에 `appear` 키프레임(scale 0 → 1, opacity 0 → 1, 150ms, 이동 후 시작).
- 애니메이션 중 들어온 입력은 버리지 않고, 현재 애니메이션을 즉시 끝낸 뒤 다음 이동을 처리(빠른 연타에도 상태가 꼬이지 않게). 로직 상태는 입력 즉시 갱신하고 화면만 뒤따른다.
- 점수 `+N`: 위로 떠오르며 사라짐(600ms).

## 6. 접근성
- **키보드**: 페이지 어디에서든(포커스가 버튼/입력에 있을 때 제외하고 방향키는 항상) 방향키·WASD로 조작. 보드 컨테이너는 `tabindex="0"`, `role="application"` 대신 `role="group"` + `aria-label="2048 게임 보드"` 로 두고 포커스 표시(`:focus-visible`) 제공. iframe 안에서는 보드를 클릭/탭하면 포커스가 iframe으로 들어오도록 보드 클릭 시 `board.focus()`.
- 버튼(새 게임, 계속하기, 다시 하기)은 실제 `<button>`, 최소 44×44px. 오버레이가 뜨면 첫 버튼으로 포커스 이동, 닫히면 보드로 포커스 복귀.
- **화면 낭독기**:
  - 점수판 숫자는 일반 텍스트로 두고, 별도의 시각적으로 숨긴(`.sr-only`) `aria-live="polite"` 영역에 이동마다 짧게 알림: “왼쪽 이동, 8점 획득, 점수 120”. 움직일 수 없는 방향이면 “그 방향으로는 움직일 수 없습니다”.
  - 승리·게임 오버는 `role="alert"`(또는 assertive live region)로 알림.
  - 보드 각 칸에는 시각적 숫자 외에 보드 전체를 읽을 수 있도록, 보드에 `aria-describedby`로 연결된 숨김 텍스트(“1행: 2, 빈칸, 4, 빈칸 …”)를 이동마다 갱신. 타일 DOM 자체는 `aria-hidden="true"`(애니메이션용 중복 요소 때문에).
- **`prefers-reduced-motion: reduce`**: 이동 transition·pop·appear·점수 떠오름을 모두 끈다(즉시 표시). 블로그와 같은 전역 규칙 + 게임 JS에서도 애니메이션 대기 시간을 0으로.
- 색만으로 정보를 전달하지 않음(타일에 항상 숫자 표시). `lang="ko"`.

## 7. 검증 계획 (Review 단계 체크리스트)

### 로직 (`test.html`에서 자동 테스트, 모두 통과해야 함)
- `slideLine`: `[2,2,2,2]`→`[4,4,0,0]`(+8), `[2,2,4,0]`→`[4,4,0,0]`(+4), `[4,4,8,8]`→`[8,16,0,0]`(+24), `[2,0,0,2]`→`[4,0,0,0]`, `[8,0,8,8]`→`[16,8,0,0]`, `[2,4,2,4]` 변화 없음, `[0,0,0,0]` 변화 없음, `[4,0,0,0]` 변화 없음, `[2,2,2,0]`→`[4,2,0,0]`
- `move`: 네 방향 각각 결과가 맞는지(같은 보드로 left/right/up/down 비교), 변화 없으면 `moved=false`
- `canMove`: 빈 칸 있음 → true / 가득 찼지만 가로 인접 같음 → true / 세로 인접 같음 → true / 체크무늬처럼 모두 다름 → false
- `addRandomTile`: 빈 칸에만 생성, 고정 `rng`로 2/4 확률 경계(0.9) 확인, 빈 칸 없으면 보드 그대로
- `newGame`: 타일 정확히 2개
- 승리: 2048 생성 시 `hasWon` true

### 브라우저 동작
- 방향키·WASD로 이동, 변화 없는 이동에는 새 타일이 안 생김
- 점수·`+N` 표시, 최고 점수가 새로고침 후에도 유지, 새 게임 시 현재 점수만 0
- 승리 오버레이 → 계속하기 후 재표시 안 됨, 게임 오버 오버레이 → 다시 하기
- 빠른 연타 시 타일 겹침·유령 타일 없음
- 방향키로 페이지가 스크롤되지 않음
- 콘솔 오류 없음

### 모바일 (375×812 에뮬레이션)
- 가로 스크롤 없음, 보드가 화면 안에 다 보임
- 스와이프 4방향 동작, 짧은 탭은 이동으로 처리 안 함(최소 거리 30px, 주축 판정)
- 스와이프 중 페이지 스크롤/당겨서 새로고침 안 됨

### 테마·접근성·iframe
- 라이트/다크 각각에서 타일 숫자 대비 확인, `theme` 저장값과 OS 설정 우선순위가 블로그와 같음
- 임시 HTML이나 개발자 도구로 `<iframe src="apps/2048/">`(예: 400×480) 안에 띄워 클릭 후 키 입력·스와이프 동작, 잘림 없음, 부모 테마 변경이 반영됨
- `prefers-reduced-motion` 에뮬레이션 시 애니메이션 없음
- Tab 순서, 오버레이 포커스 이동, live region 알림 문구

## 8. 블로그 카드(Embed) 계획
- **카드 제목**: 2048
- **한 줄 설명**: 방향키나 스와이프로 타일을 합쳐 2048을 만드는 퍼즐 게임
- **미리보기 방식(제안)**: **iframe으로 실제 게임을 카드 안에 넣고**, 아래에 “전체 화면으로 열기” 링크(`apps/2048/`)를 둔다.
  - 이유: 2048은 작은 화면에서도 바로 플레이 가능하고 외부 리소스가 없어 가볍다. 정적 이미지보다 “직접 해 볼 수 있는 포트폴리오”라는 장점이 크다. 같은 출처라 테마·최고 점수도 공유된다.
  - 주의: iframe에 `loading="lazy"`, `title="2048 게임"`, 고정 높이(예: 모바일 440px, 데스크톱 520px). 메인 페이지 스크롤 중 스와이프가 게임에 먹히는 문제를 줄이려면 보드에만 `touch-action: none`을 둔다(5장).
  - 대안: 스크린샷 이미지(`apps/2048/preview.png`) + 링크. 메인 페이지를 더 가볍고 단순하게 유지하고 싶다면 이쪽. → **사용자 결정 필요**
- Embed 작업은 Embed 단계에서 `index.html`에 카드를 추가하는 것으로, 이번 Build 범위에 포함하지 않는다.
