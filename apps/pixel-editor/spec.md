# 픽셀 아트 에디터 — 계획서 (spec)

## 1. 개요
16×16 격자에 마우스·터치·키보드로 도트를 찍어 그림을 그리고, 완성한 그림을 확대한 PNG로 저장하는 웹앱. 기본 팔레트와 사용자 지정 색을 지원한다. 화면(UI)은 블로그와 같은 라이트/다크 테마를 따르지만 **그림 데이터와 저장되는 PNG는 테마와 무관**하다. 블로그 메인 카드의 iframe 안에서도 그리기와 저장이 동작한다. HTML/CSS/JS만 쓰고 외부 라이브러리는 쓰지 않는다(PNG 생성은 Canvas API로 충분하다 — 3장).

## 2. 기능 목록

### MVP (반드시 구현) — 10장 결정에 따라 조정
| # | 기능 | 세부 |
|---|------|------|
| 1 | 16×16 격자 | 정사각형 보드. 빈 칸(투명)은 체크무늬로 표시 |
| 2 | 펜 | 칸 클릭/탭으로 현재 색 칠하기 |
| 3 | 드래그 연속 칠하기 | 누른 채 움직이면 지나간 칸을 모두 칠함. **빠르게 움직여도 칸이 빠지지 않도록** 이전 칸과 현재 칸 사이를 직선 보간(Bresenham, 3장 `cellsOnLine`)하고, `getCoalescedEvents()`가 있으면 그 점들도 모두 처리 |
| 4 | 지우개 | 칸을 투명(`null`)으로. 드래그도 펜과 동일 |
| 5 | 채우기(페인트 통) | 클릭한 칸과 같은 색(투명 포함)으로 **상하좌우** 연결된 영역을 현재 색으로. 대각선으로는 번지지 않음 |
| 6 | 색상 팔레트 | 기본 16색(5장 표). 클릭으로 선택, 선택 표시는 테두리 링 + 체크 표시(색만으로 구분하지 않음) |
| 7 | 사용자 지정 색 | `<input type="color">`. 고른 색이 "사용자 색" 칸에 표시되고 즉시 현재 색이 됨 |
| 8 | 되돌리기 / 다시 실행 | 획(stroke) 하나, 채우기 한 번, 전체 지우기 한 번이 각각 1단계. 최대 100단계. 새 동작을 하면 다시 실행 목록은 비움 |
| 9 | 전체 지우기 | 확인 창 없이 즉시 지우고(되돌리기 가능) "전체 지움 — 되돌리기로 복구할 수 있습니다" 안내. 빈 그림이면 비활성 |
| 10 | 격자선 표시 토글 | 기본 켜짐. 화면 표시만 바뀌고 PNG에는 영향 없음. 설정도 자동 저장 |
| 11 | 자동 저장 | `localStorage` 키 `pixel-editor-state`에 그림·현재 색·도구·격자선 설정 저장. 획이 끝날 때/동작마다 저장(300ms 디바운스). 저장 실패(try/catch)해도 앱은 동작. 되돌리기 기록은 저장하지 않음 |
| 12 | PNG 저장 | 투명 배경(지운 칸·빈 칸은 alpha 0). 배율 선택 1×/8×/16×/32× → 16/128/256/512px, 기본 16×. 파일 이름 `pixel-art-YYYYMMDD-HHmmss.png`(로컬 시간) |
| 13 | 테마 | 블로그와 같은 `theme` 키, 없으면 OS 설정. iframe에서 부모 변경 즉시 반영 |
| 14 | 반응형·iframe | 375px 폭 가로 스크롤 없음, 보드 위에서 그리는 동안 페이지 스크롤 없음, 카드 iframe(약 300×440) 안에서도 잘림 없음 |

### 있으면 좋은 것 (MVP 이후, 사용자가 원하면)
- **스포이트**: 칸의 색을 현재 색으로(투명 칸이면 지우개로 전환). 구현은 쉽지만 16×16에서는 팔레트로 충분해 MVP에서 뺐다 → 결정 1
- 최근 사용한 사용자 색 목록(최대 8개)
- 흰 배경 PNG 옵션 → 결정 3
- 파일 이름 직접 입력 → 결정 5
- 좌우 대칭 그리기, 선/사각형 도구, PNG 불러오기

### MVP/선택 구분 근거
- 되돌리기·다시 실행: 그림 앱에서 가장 기본적으로 기대되고, 256칸 스냅샷이라 구현이 단순하다. 확인 창 없는 전체 지우기의 안전장치도 된다 → MVP.
- 채우기: 픽셀 아트에서 배경·면 채우기에 자주 쓰고 256칸 BFS라 가볍다 → MVP.
- 격자선 토글: CSS 클래스 하나로 끝나고, 완성 그림을 미리 보는 데 필요하다 → MVP.
- 자동 저장: iframe은 메인 페이지를 새로고침하거나 스크롤로 다시 로드될 때 그림이 사라지기 쉽다. 코드가 적다 → MVP.
- 스포이트: 팔레트가 16색+사용자 색이라 효용이 작다 → 선택.

## 3. 데이터 모델과 핵심 로직 (`editor.js`, 순수 함수, DOM 없음)

### 데이터 표현
- `SIZE = 16`. 그림 `pixels`: 길이 256 배열, 인덱스 `i = y * 16 + x`. 값은 `null`(투명) 또는 소문자 `"#rrggbb"`.
- 모든 함수는 입력 배열을 **바꾸지 않고** 새 배열을 반환(바뀐 게 없으면 같은 배열을 그대로 반환해도 됨 — `changed` 판정에 사용).
- 색은 항상 불투명. 반투명 색은 범위 밖.

### 함수 목록
| 함수 | 설명 |
|---|---|
| `createPixels()` | 256개 `null` |
| `normalizeColor(str)` | `#RGB`/`#RRGGBB`(대소문자) → `#rrggbb`, 잘못된 값은 `null` |
| `setPixels(pixels, cells, color)` | `cells`(`[{x,y}]`) 위치를 `color`(또는 `null`)로. 범위 밖 좌표는 무시. 반환 `{ pixels, changed }` |
| `cellsOnLine(a, b)` | 두 칸 사이 Bresenham 직선의 모든 칸(양 끝 포함, `a`→`b` 순서). 연속한 두 칸은 x·y 각각 최대 1 차이 |
| `floodFill(pixels, x, y, color)` | 시작 칸의 색(`null` 포함)과 같은 칸을 4방향 BFS(큐)로 모아 `color`로. 시작 색 == 새 색이면 변화 없음. 반환 `{ pixels, changed }` |
| `isEmpty(pixels)` | 모두 `null`인지 |
| `createHistory(limit = 100)` / `pushHistory(h, before)` / `undo(h, current)` / `redo(h, current)` | `{ past: [], future: [] }`. push는 `past`에 이전 그림을 넣고 `future`를 비움, 길이가 limit를 넘으면 가장 오래된 것 삭제. undo/redo는 `{ history, pixels }` 반환, 할 게 없으면 그대로. 각 항목은 256칸 배열 스냅샷(최대 100×256 — 메모리 문제 없음) |
| `pixelsToRGBA(pixels, scale)` | 길이 `(16·scale)² × 4`의 `Uint8ClampedArray`. 칸마다 `scale×scale` 블록을 해당 RGB + alpha 255로, `null`은 `0,0,0,0`. **PNG의 실제 픽셀 값을 정하는 유일한 함수**(테마·CSS와 무관하고 테스트 가능) |
| `serialize(state)` / `deserialize(text)` | 저장 형식 `{ v: 1, pixels, color, tool, grid }` ↔ JSON 문자열. `deserialize`는 JSON 오류·길이≠256·잘못된 색이 하나라도 있으면 `null`(→ 빈 그림으로 시작) |
| `timestampName(date)` | `pixel-art-YYYYMMDD-HHmmss.png`(두 자리 0 채움) |

### 그리기 흐름 (main.js)
1. `pointerdown`(보드, 주 버튼/터치/펜): 활성 포인터 id 기록, `setPointerCapture`, 획 시작 전 그림을 `strokeStart`로 보관. 펜/지우개면 그 칸 칠함, 채우기면 `floodFill` 후 즉시 기록.
2. `pointermove`(같은 포인터): `getCoalescedEvents()`(없으면 이벤트 자신)의 각 점 → 칸 좌표 계산 → 마지막 칸과 다르면 `cellsOnLine(last, cur)`로 칠함. 칸 좌표는 보드 `getBoundingClientRect()`로 `floor((clientX - left) / (width / 16))`, 0~15로 자름(보드 밖으로 나갔다 들어와도 이어짐).
3. `pointerup`/`pointercancel`/`lostpointercapture`: 획 종료. 그림이 `strokeStart`와 다르면 `pushHistory(strokeStart)` + 자동 저장. 칠한 내용은 취소 시에도 유지.
4. 두 번째 손가락 등 다른 포인터는 무시. 보드에서 `contextmenu`는 막는다(길게 누르기 메뉴 방지).
5. 렌더링은 바뀐 칸만 `style.backgroundColor` 갱신(rAF로 묶음).

### PNG 생성 (Canvas API로 충분, 라이브러리 불필요)
1. `canvas.width = canvas.height = 16 * scale` (화면에 붙이지 않는 메모리 캔버스).
2. `ctx.putImageData(new ImageData(pixelsToRGBA(pixels, scale), w, h), 0, 0)` — `fillRect`·`drawImage` 대신 픽셀을 직접 쓰므로 안티앨리어싱·스무딩·색 관리 영향이 없다.
3. `canvas.toBlob(cb, 'image/png')` → `URL.createObjectURL` → 임시 `<a download="파일이름">` 클릭 → `revokeObjectURL`(약 1초 뒤).
4. `toBlob`이 `null`이거나 예외면 "저장하지 못했습니다" 알림.
- **iframe**: 블로그 카드 iframe은 같은 출처이고 `sandbox`가 없으므로 `<a download>`가 그대로 동작한다(`sandbox`를 쓰면 `allow-downloads`가 필요 — Embed 단계에서 `sandbox`를 붙이지 않는다). iOS Safari 13+도 `download` 속성 지원. Review에서 실제로 확인한다.

## 4. 파일 구조
```
apps/pixel-editor/
├── index.html   # 마크업. head 인라인 스크립트로 테마를 CSS보다 먼저 적용(깜빡임 방지)
├── style.css    # 색상 변수(블로그 값 복사), 레이아웃(container query), 보드·팔레트·도구, 다크 모드, reduced-motion
├── editor.js    # 순수 로직 (ES module export) — 3장 함수 목록. DOM·localStorage·Canvas 접근 없음
├── main.js      # 화면·입력 — 상태 보관, 포인터/키보드 처리, 렌더링, 팔레트·도구, 자동 저장,
│                #   PNG 저장(Canvas), aria-live 알림, 테마 동기화 (editor.js import)
├── test.html    # editor.js 단위 테스트 결과를 표로 표시(통과/실패 개수 요약)
├── spec.md      # 이 문서
└── agents/      # 서브에이전트 지침
```
- 외부 라이브러리·CDN 없음. 블로그 `css/`·`js/`를 import하지 않는다(값만 복사).
- `type="module"` 사용 → 로컬 서버(예: `http://localhost:8000/apps/pixel-editor/`)로 연다.

## 5. 화면 구성

### 레이아웃
`.app`은 높이 `100dvh`(대비 `100vh`)의 세로 flex, 보드 영역이 남은 공간을 쓰고 보드 크기는 `min(100cqw, 100cqh, 480px)`(2048 재검증에서 효과가 확인된 방식). 칸 크기 = 보드 / 16.

**좁은 화면 (폭 < 600px) — 세로 배치**
```
[ 픽셀 아트 에디터 ]                 (높이 < 560px이면 설명 줄 숨김)
[          16×16 보드 (정사각형)          ]
[ 펜 | 지우개 | 채우기 | ↶ | ↷ ]            도구 줄 (44px 버튼)
[ 팔레트 16색 (8×2) + 사용자 색 ]
[ 격자선 | 전체 지우기 | 배율 ▾ | PNG 저장 ]
```
- 375×812: 좌우 16px 여백 → 보드 343px(칸 약 21px).
- 카드 iframe(약 301×440, 블로그 `.app-frame iframe` 높이 440px·카드 패딩 제외 폭): 패딩 8px, 제목 한 줄만. 버튼 줄 44+44, 팔레트 2줄(칸 28px) ≈ 60, 간격 포함 약 220px → 보드 약 200px(칸 12.5px). 잘림·가로 스크롤 없어야 한다.
- 버튼이 한 줄에 안 들어가면 줄바꿈(`flex-wrap`), 가로 스크롤 금지.

**넓은 화면 (폭 ≥ 600px) — 가로 배치**: 보드 왼쪽(최대 480px), 오른쪽 패널(폭 180~220px)에 도구 → 팔레트(4×4) → 사용자 색 → 격자선/전체 지우기 → 배율/PNG 저장. 데스크톱 카드 iframe(높이 520px)에서 보드 약 480px.

### 보드
- 16×16 CSS grid의 `div` 256개(`aria-hidden`, 접근성은 6장). 칸 배경은 데이터 색을 인라인 style로.
- 투명 칸: 칸마다 2×2 체크무늬(`--checker-a`, `--checker-b`, 테마별). 표시 전용.
- 격자선: 켜면 칸에 `box-shadow: inset 0 0 0 0.5px var(--grid-line)`(또는 오른쪽·아래 1px). 색 칸 크기는 바뀌지 않게.
- 키보드 커서 칸: 두 겹 링(바깥 `--accent`, 안쪽 `--bg`) — 어떤 칸 색 위에서도 보이게. 포커스가 보드에 있을 때만 표시.
- `.board { touch-action: none; user-select: none; -webkit-touch-callout: none; }` — 그리는 동안 스크롤·당겨서 새로고침·확대·길게 누르기 메뉴 방지. 페이지 나머지는 막지 않음.
- 커서: 펜/채우기 `crosshair`, 지우개는 같은 커서 + 도구 표시로 구분.

### 팔레트 (기본 16색)
`#000000` 검정, `#ffffff` 흰색, `#9e9e9e` 회색, `#5d4037` 갈색, `#e53935` 빨강, `#fb8c00` 주황, `#fdd835` 노랑, `#7cb342` 연두, `#2e7d32` 초록, `#00acc1` 청록, `#1e88e5` 파랑, `#3949ab` 남색, `#8e24aa` 보라, `#f06292` 분홍, `#ffccbc` 살구, `#424242` 진회색.
- 각 칸은 `<button>`, 기본 32px(iframe 좁은 화면 28px). 흰색·검정이 어느 테마에서도 보이도록 모든 칸에 1px `--border` 테두리.
- 선택: `aria-pressed="true"` + 두 겹 링 + 가운데 체크 표시(밝은 색 위엔 검정, 어두운 색 위엔 흰색 — 밝기로 계산).
- 사용자 색: 팔레트 끝에 `<label>`로 감싼 `<input type="color">` 칸(무지개 아이콘 + 현재 사용자 색). `input` 이벤트로 즉시 현재 색 변경. 사용자 색도 선택 표시 동일.
- 지우개 선택 시 팔레트 선택 표시는 유지하되 "현재: 지우개" 상태 표시. 색을 고르면 펜으로 자동 전환.

### 색상 (UI 전용)
- 공통 변수는 `css/style.css`에서 복사: 라이트 `--bg #ffffff`, `--bg-elevated #ffffff`, `--text #1f2328`, `--text-muted #59636e`, `--accent #2563eb`, `--accent-soft #eff4ff`, `--border #e5e7eb` / 다크 `#16171a`, `#1c1e22`, `#e6e6e6`, `#9aa0a6`, `#60a5fa`, `#1b2638`, `#2d2f34`. 글꼴 `--font-sans` 복사.
- 앱 전용: `--checker-a/-b`(라이트 `#ffffff`/`#e5e7eb`, 다크 `#2d2f34`/`#3a3d43`), `--grid-line`(라이트 `rgba(0,0,0,.15)`, 다크 `rgba(255,255,255,.15)`), `--board-frame`.
- **테마 무관성 규칙**: 그림 칸 색은 오직 데이터(`pixels`)에서 오고 CSS 변수를 쓰지 않는다. PNG는 `pixelsToRGBA`만 사용. 테마가 바뀌는 것은 체크무늬·격자선·UI뿐.

### 테마 적용 (2048과 동일)
- head 인라인 스크립트: `localStorage.theme`(`light|dark`) → 없으면 `prefers-color-scheme` → `<html data-theme>`.
- CSS: `:root[data-theme="dark"]` + JS 꺼짐 대비 `@media (prefers-color-scheme: dark) :root:not([data-theme])`.
- main.js: 저장값 없을 때 `matchMedia change` 따라감, `storage` 이벤트(`key === 'theme'`)로 부모 블로그 변경 즉시 반영. 앱 안 테마 토글 없음.

## 6. 접근성
- **키보드로 그리기 가능**: 보드는 `tabindex="0"`, `role="application"`이 아닌 `role="group"` + `aria-label="16×16 그림판"` + `aria-describedby`(조작법 숨김 텍스트).
  - 방향키: 커서 이동(가장자리에서 멈춤), Home/End: 행 처음/끝.
  - Space/Enter: 커서 칸에 현재 도구 적용(펜·지우개·채우기). Shift+방향키: 이동하면서 칠하기(이어지는 이동은 한 획으로 묶지 않고 각각 1단계여도 됨).
  - 보드 키 처리 시 `preventDefault()`로 페이지 스크롤 방지.
- 전역 단축키(포커스가 `input`에 있을 때 제외, 한글 자판 대비 `event.code` 사용): `B` 펜, `E` 지우개, `F` 채우기, `Ctrl/Cmd+Z` 되돌리기, `Ctrl/Cmd+Shift+Z`·`Ctrl+Y` 다시 실행, `G` 격자선. 단축키는 버튼 `title`과 `aria-keyshortcuts`에 표시.
- 도구 버튼: `<button aria-pressed>`(펜/지우개/채우기는 하나만 true), 아이콘 + 텍스트 라벨(좁은 화면에서는 시각적으로 숨긴 텍스트 + `aria-label`). 되돌리기/다시 실행/전체 지우기는 할 수 없을 때 `disabled`. 모든 버튼 최소 44×44px(팔레트 칸은 28~32px — WCAG 2.5.8 최소 24px 충족).
- 팔레트 버튼 `aria-label="빨강 #e53935"`, 사용자 색 `aria-label="사용자 색 고르기, 현재 #rrggbb"`.
- 배율 선택은 `<label>` 붙은 `<select>`.
- **화면 낭독기**: `.sr-only` `aria-live="polite"` 영역에 짧게 알림 — 커서 이동 "3행 5열, 빨강"(팔레트 색이면 이름, 아니면 hex, 빈 칸이면 "비어 있음"), 칠하기 "칠함", 도구/색 변경, "되돌림", "다시 실행", "전체 지움", "PNG 저장: 파일이름 (256×256)". 연속 알림은 타이머 토큰으로 마지막 것만 남김(2048 교훈). 드래그 중에는 알리지 않는다.
- 오버레이/대화 상자는 없다(전체 지우기 확인 창 없음). 결정 2에서 확인 창을 택하면 `role="dialog"`, `aria-modal`, 포커스 순환·복귀를 적용(2048 교훈).
- **`prefers-reduced-motion: reduce`**: 버튼 전환·안내 토스트 페이드 등 모든 transition/animation 끔. 토스트는 즉시 표시·제거.
- `lang="ko"`, 포커스 표시 `:focus-visible` outline.

## 7. 검증 계획 (Review 단계 체크리스트)

### 로직 (`test.html`, 모두 통과)
- `normalizeColor`: `#ABC`→`#aabbcc`, `#FF0000`→`#ff0000`, `red`/`#12345`/`''`→`null`
- `setPixels`: 지정 칸만 변경, 원본 불변, 범위 밖 무시, 같은 색이면 `changed=false`
- `cellsOnLine`: 같은 점(1칸), 가로·세로·45° 대각선, 완만/가파른 기울기, 역방향, 양 끝 포함, 연속 칸 간격 ≤1, (0,0)→(15,15)는 16칸
- `floodFill`: 빈 그림 전체 256칸, 닫힌 테두리 안쪽만, 대각선 틈으로 새지 않음, 같은 색이면 변화 없음, `null`로 채우기(지우기), 원본 불변
- 히스토리: undo→redo 왕복, 새 push 후 `future` 비움, limit 초과 시 오래된 것 삭제, 빈 상태에서 undo/redo는 그대로
- `pixelsToRGBA`: scale 1·16의 길이, 특정 칸 블록의 RGBA 정확값, `null`은 alpha 0, 블록 경계(스케일 블록이 옆 칸 색과 섞이지 않음)
- `deserialize`: 정상 왕복, 깨진 JSON·길이 오류·잘못된 색 → `null`
- `timestampName`: 한 자리 월/일/시 0 채움

### 브라우저 동작
- 클릭 칠하기, 드래그 연속 칠하기, **빠른 드래그(합성 이벤트로 멀리 떨어진 두 점 사이 이동)에도 빈 칸 없음**, 보드 밖으로 나갔다 들어와도 정상
- 지우개, 채우기, 되돌리기/다시 실행(획 단위), 전체 지우기 후 되돌리기 복구, 버튼 disabled 상태
- 팔레트 선택 표시, 사용자 색 선택, 색 선택 시 펜 자동 전환
- 격자선 토글, 새로고침 후 그림·색·도구·격자선 복원, `localStorage`에 깨진 값을 넣어도 빈 그림으로 시작
- 콘솔 오류 없음, `innerHTML` 미사용, 외부 리소스 없음

### PNG 결과물
- 각 배율(1/8/16/32×)에서 파일 크기(16/128/256/512px) 확인
- 다운로드된 PNG(또는 같은 경로로 만든 Blob)를 `Image`로 다시 읽어 캔버스 `getImageData`로 몇 칸 샘플: 칠한 칸 RGB가 데이터와 정확히 일치·alpha 255, 빈/지운 칸 alpha 0, 블록 경계 번짐 없음
- 격자선·체크무늬·커서 링이 PNG에 없음
- 파일 이름 형식

### 모바일 (375×812 에뮬레이션)
- 가로 스크롤 없음(`scrollWidth = 375`), 보드 343px, 모든 컨트롤 화면 안
- 터치(합성 PointerEvent touch) 탭·드래그 칠하기, 두 번째 포인터 무시, `pointercancel` 시 획 정상 종료
- 보드의 `touch-action: none` 계산값, 그리는 동안 페이지 스크롤 없음(실기기는 사람이 확인 권장)

### 테마 무관성·iframe·접근성
- 라이트에서 그림 → 다크 전환 → 칸 색 동일, 두 테마에서 만든 PNG의 RGBA 배열이 바이트 단위로 같음
- 체크무늬·격자선·선택 링이 두 테마에서 보임, 텍스트 대비 4.5:1 이상
- 블로그 메인에 임시로 iframe 삽입(파일 미생성) 300×440, 400×480, 700×520: 잘림·가로 스크롤 없음, 그리기 동작, **iframe 안에서 PNG 다운로드 동작**, 부모 테마 변경 반영
- 키보드만으로: Tab 순서, 방향키 커서 이동·Space 칠하기·채우기, 단축키(한글 자판 상태 포함), `aria-pressed` 상태, live region 문구
- reduced-motion: 코드 확인(도구에 에뮬레이션이 없으면 미확인으로 기록)
- 검증 후 `localStorage`(`pixel-editor-state`, `theme`)와 화면 에뮬레이션을 원래대로 되돌림

## 8. 블로그 카드(Embed) 계획
- **카드 제목**: 픽셀 아트 에디터
- **한 줄 설명**: 16×16 격자에 도트를 찍어 그리고 PNG로 저장하는 그림판
- **미리보기 방식(제안)**: 2048과 같은 **iframe**(`title="픽셀 아트 에디터"`, `loading="lazy"`, `sandbox` 없음) + "전체 화면으로 열기" 링크(`apps/pixel-editor/`).
  - 이유: 직접 그려 볼 수 있는 포트폴리오라는 장점, 카드 형식 일관성, 같은 출처라 테마·자동 저장·다운로드가 그대로 동작.
  - 주의: 모바일 카드(약 301×440)에서는 보드가 약 200px(칸 12px)로 작아 손가락으로 정밀하게 그리기 어렵고, 보드 위에서는 메인 페이지 스크롤이 막힌다(보드 영역만). 그래서 좁은 iframe에서도 "전체 화면으로 열기"를 눈에 띄게 둔다. 카드 높이를 이 앱만 늘리려면 Embed 단계에서 블로그 CSS에 수정자 클래스가 필요하다(현재 높이 440/520 공용).
  - 대안: 예시 그림이 그려진 스크린샷 이미지(`apps/pixel-editor/preview.png`) + 링크. 메인 페이지가 가볍고 모바일 스크롤 방해가 없다 → **결정 7**
- Embed 작업(`index.html` 카드 추가)은 Build 범위에 포함하지 않는다.

## 10. 사용자 결정이 필요한 점 (제안안 — 위 "사용자 결정"이 우선)
1. **추가 도구 범위** — 제안: 되돌리기/다시 실행·채우기·격자선 토글·자동 저장은 MVP, **스포이트는 제외**(있으면 좋은 것). 대안: 스포이트도 MVP에 포함.
2. **전체 지우기 확인** — 제안: 확인 창 없이 즉시 지우고 되돌리기로 복구(안내 문구 표시). 대안: 앱 안 확인 대화 상자("모두 지울까요?").
3. **PNG 배경** — 제안: 투명 배경만. 대안: "흰 배경" 체크박스 추가.
4. **저장 배율** — 제안: 1×/8×/16×/32× 선택, 기본 16×(256×256px). 대안: 고정 16× 한 가지만(UI 단순).
5. **파일 이름** — 제안: 자동 `pixel-art-YYYYMMDD-HHmmss.png`. 대안: 이름 입력칸(비우면 자동 이름).
6. **기본 팔레트** — 제안: 5장의 16색 + 사용자 색 1칸. 대안: 다른 색 구성(예: 8색으로 줄이기)이나 최근 사용자 색 목록 추가.
7. **카드 미리보기** — 제안: 2048처럼 iframe + "전체 화면으로 열기". 대안: 스크린샷 이미지 + 링크(모바일에서 작고 스크롤을 막는 문제 회피).
8. **앱 안 테마 토글** — 제안: 넣지 않음(2048과 동일, 블로그·OS 설정만 따름).
9. **격자선 기본값** — 제안: 켜짐. 대안: 꺼짐.
