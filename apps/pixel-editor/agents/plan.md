# Plan 서브에이전트 지침 — 픽셀 아트 에디터

## 너의 역할
픽셀 아트 에디터 웹앱의 **계획서(spec)만** 작성한다. 코드는 쓰지 않는다.

## 수정 범위 (이 밖의 파일은 절대 만들거나 고치지 않는다)
- 만들 파일: `apps/pixel-editor/spec.md` 하나

읽기는 자유롭게 해도 된다. 특히 아래를 참고한다.
- `CLAUDE.md` — 프로젝트 규칙과 작업 사이클
- `css/style.css`, `js/theme.js` — 블로그 색상 변수와 라이트/다크 모드(`localStorage`의 `theme` 키, 없으면 OS 설정)
- `apps/2048/spec.md`, `apps/2048/review.md` — 이전 웹앱의 계획서 형식과 검증에서 나온 교훈(iframe 높이, 오버레이 포커스, reduced-motion, 테마 동기화 등). 같은 형식과 수준으로 쓴다.
- `index.html`의 "미니 웹앱" 카드 — 이 앱도 나중에 같은 방식으로 카드로 들어간다

## 사용자 요청
> 픽셀 아트 에디터를 만들어줘. 16x16 격자에 도트를 찍어서 그림을 그리고, 완성하면 PNG로 저장할 수 있게 해줘. 색상 팔레트도 넣어줘.

## 지켜야 할 조건
- HTML, CSS, JavaScript만 사용. 빌드 도구·npm 없음. 외부 라이브러리는 꼭 필요할 때만(CDN 허용), 가능하면 쓰지 않는다. PNG 저장은 Canvas API로 충분한지 검토한다.
- 앱은 `apps/pixel-editor/` 안에서 자체 완결된다. 블로그의 CSS/JS를 import하지 않는다(값 복사는 가능).
- 모바일에서도 사용 가능: 마우스와 터치로 그리기(드래그로 연속 칠하기 포함), 375px 폭에서 가로 스크롤 없음, 그리는 동안 페이지가 스크롤되지 않음.
- 블로그처럼 라이트/다크 모드를 따른다. 단, **그림 자체의 색과 저장되는 PNG는 테마와 무관**해야 한다.
- 블로그 메인 카드의 iframe 안에서도 동작해야 한다. iframe 안에서 파일 다운로드가 되는지(같은 출처, sandbox 없음)도 계획에 고려한다.

## spec.md에 반드시 들어갈 내용
1. **개요**
2. **기능 목록** — MVP와 있으면 좋은 것을 구분. 최소한 다음을 포함:
   - 16×16 격자, 칸 클릭/탭으로 칠하기, 드래그로 연속 칠하기(빠르게 움직여도 칸이 빠지지 않게 하는 방법 포함)
   - 색상 팔레트(기본 색 몇 개, 선택 표시) + 사용자 지정 색 고르기
   - 지우개(투명), 전체 지우기(확인 필요 여부 포함)
   - PNG 저장: 투명 배경 여부, 저장 배율(16×16 그대로는 너무 작으므로 확대 저장 옵션), 파일 이름
   - 그 밖에 기본적으로 기대되는 도구(예: 되돌리기, 스포이트, 채우기, 격자선 표시 토글, 작업 자동 저장)는 MVP인지 선택인지 근거와 함께 구분하고, 사용자에게 물어볼 점으로 정리
3. **데이터 모델과 핵심 로직** — 그림 데이터 표현, 칠하기/채우기/되돌리기 알고리즘(포함한다면), PNG 생성 방법
4. **파일 구조** — 로직(순수 함수)과 화면을 분리해 로직만 테스트할 수 있게 한다. `test.html` 포함.
5. **화면 구성** — 데스크톱/모바일 레이아웃, 격자 크기 계산, 팔레트·도구 배치, 라이트/다크 색
6. **접근성** — 키보드로 칸 이동·칠하기 가능 여부, 도구·색 선택 버튼의 상태 표시, 화면 낭독기 안내, `prefers-reduced-motion`
7. **검증 계획** — Review 단계에서 확인할 항목(브라우저 동작, 모바일 터치, PNG 결과물의 크기·픽셀 색 정확성·투명도, iframe, 테마 무관성, 로직 엣지 케이스)
8. **블로그 카드(Embed) 계획** — 제목, 한 줄 설명, 미리보기 방식(이전 2048처럼 iframe이 맞는지, 다른 게 나은지)과 이유
9. **범위 밖**
10. **사용자 결정이 필요한 점** — 번호 목록, 각 항목에 제안안 표시

## 작성 규칙
- 한국어로, 구현자가 이것만 보고 만들 수 있을 만큼 구체적으로. 불필요하게 길게 쓰지 않는다.
- 끝나면 파일 구조, MVP 기능, 결정이 필요한 점을 짧게 요약해 보고한다.
